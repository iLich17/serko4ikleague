# F1 League — Python hosting

Сайт можно запускать без Flask/Django и без установки зависимостей.

## 1. Запуск на сервере

Требуется Python 3.9+.

```bash
cd f1site_hosting
python3 server.py
```

По умолчанию сайт будет слушать:

```text
http://0.0.0.0:8080
```

С локального компьютера/сервера:

```text
http://IP_СЕРВЕРА:8080
```

Можно изменить порт:

```bash
PORT=8000 python3 server.py
```

Для Linux обычно нужно открыть TCP-порт в firewall, если к нему обращаются напрямую.

## 2. Свой домен

Сам Python-сервер не покупает домен. Домен регистрируется у любого регистратора, а DNS направляется на IP твоего сервера.

Например, если домен:

```text
f1league.ru
```

и IP сервера:

```text
203.0.113.10
```

в DNS создай:

```text
Type: A
Name: @
Value: 203.0.113.10
```

Для `www`:

```text
Type: A
Name: www
Value: 203.0.113.10
```

После обновления DNS домен будет указывать на сервер.

## 3. Важно: HTTPS

Для настоящего домена лучше не выставлять Python `:8080` напрямую в интернет.
Рекомендуемая схема:

```text
Интернет
   ↓
f1league.ru:443
   ↓
HTTPS reverse proxy (Caddy/Nginx)
   ↓
Python server.py :8080
```

Reverse proxy получает SSL-сертификат для домена и передаёт запросы Python-серверу.

### Вариант с Caddy

Установи Caddy на сервере и создай `Caddyfile`:

```text
f1league.ru {
    reverse_proxy 127.0.0.1:8080
}
```

Если нужен `www`:

```text
f1league.ru, www.f1league.ru {
    reverse_proxy 127.0.0.1:8080
}
```

После запуска Caddy он автоматически запросит Let's Encrypt-сертификат,
если DNS уже указывает на сервер и порты 80/443 доступны.

Python при этом запускается:

```bash
python3 server.py
```

## 4. Чтобы Python-сервер работал после выхода из SSH

Самый простой вариант для Linux — systemd.

Создай:

```text
/etc/systemd/system/f1league.service
```

Содержимое:

```ini
[Unit]
Description=F1 League website
After=network.target

[Service]
Type=simple
WorkingDirectory=/var/www/f1league
ExecStart=/usr/bin/python3 /var/www/f1league/server.py
Restart=always
RestartSec=3
Environment=HOST=127.0.0.1
Environment=PORT=8080

[Install]
WantedBy=multi-user.target
```

Затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now f1league
sudo systemctl status f1league
```

## 5. Срочные новости — общие для всех

Срочные новости теперь хранятся **на сервере** в файле:

```text
news.json
```

Когда любой посетитель нажимает «Опубликовать», браузер отправляет новость на:

```text
POST /api/news
```

Другие посетители получают те же новости через:

```text
GET /api/news
```

Поэтому новость больше не хранится в `localStorage` конкретного браузера и после публикации отображается у всех, кто открыл сайт. Список автоматически обновляется примерно раз в 30 секунд, а после публикации у автора обновляется сразу.

Важно: сервер должен быть запущен через `server.py`. Если открыть `index.html` напрямую как файл, общий API новостей работать не будет.

## 6. Обновление результатов

Замени файл:

```text
results.json
```

на новый и обнови страницу.

Python-сервер специально отдаёт `results.json` без кеширования, поэтому новые результаты будут подхватываться сразу.

## 7. Структура

```text
f1league/
├── index.html
├── results.json
├── news.json
├── server.py
└── assets/
    ├── ...
```

Папку `assets/` из твоего проекта нужно сохранить рядом с `index.html`.

## 8. Проверка

Проверка сервера:

```text
http://127.0.0.1:8080/health
```

Должно вернуться:

```json
{"status":"ok","service":"f1-league"}
```

Главная:

```text
http://127.0.0.1:8080/
```

После настройки DNS + HTTPS:

```text
https://f1league.ru/
```


## 9. Регистрация пользователей

Теперь для просмотра сайта пользователь должен зарегистрироваться или войти. Открой `http://127.0.0.1:8080/auth`.

Регистрация требует:
- ник 3–24 символа (буквы, цифры, `_`, `-`, `.`);
- пароль от 6 символов.

Аккаунты сохраняются на сервере в `users.json`. Пароли **не хранятся в открытом виде**: используется PBKDF2-HMAC-SHA256 с солью. Поэтому даже при просмотре файла `users.json` реальные пароли не видны.

После входа сессия хранится в защищённой cookie и действует до 12 часов с продлением при активности. После перезапуска Python-сервера пользователю потребуется войти заново, но сам аккаунт и пароль останутся сохранены в `users.json`.

Обычные пользователи могут смотреть сайт и новости, но публиковать новости не могут. Публикация/редактирование/удаление новостей доступна только зарегистрированным пользователям, чьи ники указаны в `admins.json`. В `/admin` вход выполняется по нику и паролю пользователя.


## Администраторы

Список администраторов хранится в `admins.json`. Добавлять туда можно только уже зарегистрированные ники. Например:

```json
[
  "admin",
  "мой_ник"
]
```

Только пользователи из этого списка получают доступ к публикации, редактированию и удалению новостей.

В комплекте есть стартовый администратор: `admin` / `f1admin`. После проверки работы сайта рекомендуется зарегистрировать свой аккаунт, добавить его ник в `admins.json` и удалить `admin` из списка.


### Исправление Кубка конструкторов
Для каждого сезона команда пилота определяется по `season_rosters.json` и конкретному этапу. Это исключает перенос состава/команды из другого сезона и корректно считает очки, победы и подиумы конструкторов.
