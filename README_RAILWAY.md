# F1 League — Railway deployment

Проект подготовлен для Railway. Дополнительные Python-зависимости не нужны.

## 1. Загрузка

Загрузите этот проект в GitHub и в Railway выберите **Deploy from GitHub Repo**.
Railway автоматически использует `Dockerfile`.

## 2. Persistent Volume — ОБЯЗАТЕЛЬНО

В Railway откройте сервис → **Volumes** → создайте Volume и установите mount path:

```text
/data
```

Переменная `F1_DATA_DIR=/data` уже задана в Dockerfile.

Это необходимо, чтобы после перезапуска/нового деплоя не потерялись:

- `users.json` — зарегистрированные пользователи;
- `admins.json` — список администраторов;
- `news.json` — новости.

При первом запуске существующие файлы из проекта автоматически копируются в Volume.

## 3. Public URL

После Deploy откройте Railway → сервис → **Settings / Networking** и сгенерируйте публичный домен.

Сайт будет доступен по адресу Railway вида `https://....up.railway.app`.

## 4. Администраторы

Список находится в `/data/admins.json` на Volume.

Сейчас в проекте:

```json
[
  "admin",
  "burmalda"
]
```

Пользователь также должен существовать в `users.json`, иначе вход в админку невозможен.

## 5. Важно перед публикацией

1. Не публикуйте `users.json` или `admins.json` напрямую.
2. Используйте HTTPS-домен Railway.
3. Сделайте резервную копию Volume перед серьёзными изменениями.
4. Не удаляйте Volume при удалении/пересоздании сервиса.
5. Для production рекомендуется сменить тестовый аккаунт `admin` или удалить его из `admins.json` после создания своего администратора.

## 6. Локальный запуск

```bash
python server.py
```

По умолчанию данные остаются в папке проекта. Для проверки Railway-поведения локально можно задать:

```bash
F1_DATA_DIR=./data python server.py
```
